# Staff-managed league rosters

Owner and existing administrators use `/admin?tab=players` to add league player records by Discord name and assign/release them separately in Season 2 6v6 and 10v10. No OAuth account is created or privileged by adding a name. Names are entered by staff, not verified against Discord guild membership. Only the Owner still appoints administrators through Members.

`migrations/0012_league_rosters.sql` seeds the existing Season 2 snapshot while preserving profile IDs, artwork metadata and confirmed identity aliases. It uses INSERT OR IGNORE and cannot overwrite later staff assignments if rerun. Season 1 snapshots, official VA fixtures/standings, picks and the bot database are unchanged. The bot is not synchronized to these new assignments yet.

Assignments are keyed by player, season and division, enforcing one team per division. Release sets the team to NULL while retaining the record and portrait. Unassigned players remain in the searchable pool; public Players includes a Free agents filter. Public rosters fetch the shared database when opened, with a 15-second in-page freshness window. Changes are not pushed into an already-open, idle browser.

The original imported snapshot remains a browser fallback if the roster service is temporarily unavailable. No API failure is interpreted as deletion of a roster. Admin writes require an active owner/admin session, same-origin requests, server-validated clubs and an audit entry. Discord-name duplicates are rejected; ambiguous existing same-name records are preserved rather than guessed/merged.

New players automatically work with private photo review and approval. Catalog clubs are generated by `node scripts/build-roster-seed.mjs`; rebuild when adding clubs, but do not use that generator to migrate new seasons without a new season-specific migration.

Verification: `node --test scripts/league-rosters.test.mjs scripts/player-photos.test.mjs scripts/league-pages.test.mjs scripts/navigation-scroll.test.mjs`. Authenticated UI acceptance requires a real signed-in administrator; never forge a production session.
